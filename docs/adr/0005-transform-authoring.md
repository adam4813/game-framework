# Author `Transform`, Never `WorldTransform` Directly

`WorldTransform` (world-space position, rotation, scale, and matrix) is exclusively computed and owned by the engine: seeded from `Transform` whenever it is set, by the `TransformSeedWorldTransform` observer, then updated every frame by `TransformPropagation` (for all entities) or by the physics backend (for dynamic rigid bodies). Game and engine code write only `Transform` (local-space). Any direct write to `WorldTransform` after initialisation is silently overwritten on the next frame by `TransformPropagation`, producing bugs that are very hard to trace because the value appears correct at the point of writing.

**Reading it before the first frame.** `TransformPropagation` computes `WorldTransform` from the `ChildOf` hierarchy, and it runs only when the world progresses. Until then (in a scene's `Load`, or a level-build pass called from it) `WorldTransform` holds the seed made when `Transform` was last set, composed with the parent's `WorldTransform` at that moment, so it goes stale if a parent moves afterwards. Code that runs before the first frame reads `Transform`, composing parents itself where they carry a transform.
